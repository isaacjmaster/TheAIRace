# Two GPU racks and independent robotics buildings

Approved for publication together with the preceding HQ life/audio polish. Checkpoint: `checkpoint/pre-two-rigs-independent-hangar`.

- Maximum two GPU Rigs, enforced in the authoritative game logic. Construction occupies a slot. The Build card shows 0/2, 1/2 or 2/2 and disables at the limit. One Builder Bot still constructs one building at a time.
- Existing `rig` remains rack 1 unchanged. Optional `rig2` holds the second rack. Each costs 50 Compute, takes 15 seconds, generates 5 Compute/minute and stores 25 independently. Each has its own collection badge, fan/activity animation, hit target and movement/rotation identity. Collection requests can specify rig2; omitted targets keep the original first-rack contract and receipt payloads. Total player capacity remains 1000.
- New Bot Fabricator purchases no longer create or reserve a Hangar. The Build menu offers Bot Fabricator and Bot Hangar separately. The Fabricator remains 50 Compute; the Hangar remains free, preserving the original combined Compute cost. Each takes 15 seconds using the same builder. Either can be placed first and relocated independently. Training requires both completed buildings; troop cost, sequential timing and ten-bot army capacity are unchanged.
- New Hangars use an optional `hangar` record. New Fabricators have `separateHangar:true`; their legacy companion fields are retained for format compatibility but confer no Hangar ownership. `getHangar` is the single access path for effective ownership/layout. Old Fabricators without the flag retain their existing Hangar at its exact saved position/rotation, including construction timing, without repurchasing. Moving an old Hangar updates its existing legacy fields; no automatic save rewrite or database schema migration occurs.
- Bot walking uses the independently saved Hangar endpoint. Idle motions, building-specific sounds, GPU activity and the blocked-doorway cosmetic fallback remain. Identity, names, recovery codes, Ava, raids, rewards, fullscreen presentation and Railway settings are unchanged.
- Reset clears both GPU slots and both robotics buildings while retaining company identity/recovery and the existing verified raid-history policy. Retry receipts, reset generations, transactions and company guards continue to protect every purchase, move and collection.
